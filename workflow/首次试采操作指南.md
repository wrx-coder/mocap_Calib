# 动捕与 D435i：首次试采操作指南

> **适合谁**：第一次进入动捕场地、能看相机画面，但还不熟悉刚体、数据导出和配对的人。
> **今天的目标**：选一颗两套设备都能测的球，带回能解释、能配对、能离线处理的小批数据。**不是当天就宣布外参标定成功。**
> 相机已确认是 D435i，内参已标定，不需要重新做内参标定。软件已有离线处理工具，但没有能适配任意现场的自动采集脚本。

## 先看这张三步表

**上机采集只有下面三步。** 后文的短检查是各步骤内的具体动作，附录中的异常测试按需做，不是额外必跑关卡。

| 上机步骤 | 你做什么 | 为什么做 | 结束时应有的东西 |
|---|---|---|---|
| **第一步：准备设备，选球，确认能录** | 固定相机与胸部刚体；核对动捕导出；筛球；录一小段并回看 | 避免单位错、球心不同、画面能看却没保存数据 | 设置照片、球尺寸、短录制、真实CSV与相机数值数据 |
| **第二步：采集编号静态位置** | 同时录两侧，采15个位置，每点停3–5秒，记对应片段 | 给离线求解提供一一对应的点，而不是一段说不清的运动 | 15个位置的录制和双侧时间段/编号记录 |
| **第三步：导出，核对，备份** | 导出动捕CSV、打开相机录制、核对编号、复制备份 | 在离场前发现漏录，不回办公室才发现全批不可用 | 原文件、配对日志、配置、异常记录、备份 |

## 进场前：带什么，谁来协助

- 联系熟悉场地的管理员：确认系统已经标定、允许录制、可以保存/导出数据。**不自己移动动捕相机、重设世界坐标或修改正式刚体。**
- 带电脑、充足存储和可靠供电；准备拍设置和布置照片的设备。
- 带尺子/卡尺、哑光遮挡物、稳定的球支撑。支撑尽量细，不遮住大半个球。
- 准备一颗独立的小反光球和一个测试夹具。测试夹具上固定4–5颗小球，避免排成一条直线，建议非对称、略有前后错层。
- 现场有多种尺寸时，选2–3颗接近目标尺寸的**整球**作候选。苹果大小可从直径约60–80mm筛起，但这只是起步建议，最终按实物与检测效果选。
- 机器人安全支撑，躯干保持静止。**只运行感知与录制，不启动控制、抛球或接球。**

### 先分清三种球

| 名称 | 放哪里 | 用途 | 不要做什么 |
|---|---|---|---|
| 胸部刚体 marker（反光标记球） | 固定在胸部刚性结构上 | 一组点共同给出胸部位置和朝向 | 不贴到活动关节、线缆、软垫或松动外壳 |
| 共同靶球 | 放在相机前工作空间，逐位置移动 | 相机和动捕测同一颗球的同一个中心 | 不用大球表面的小球中心冒充大球中心 |
| torso 特征 marker（躯干模型对齐用球） | 已知CAD特征处 | 把动捕胸部坐标对到机器人 `torso_link` | 没有可靠特征坐标时不要凭外观估位置 |

**刚体（Rigid Body）**是一组点间距离固定的结构，软件据此给出位置和朝向；**散点（Marker）**是一颗球的实测三维位置。共同靶球不必加入胸部刚体。软件里的“资产点”可能是按刚体模板推算的位置，不用来代替独立实测散点。

### 胸部marker怎么选、贴哪里、怎样排列

**选多大**：优先使用现场已验证可跟踪的标准小球，例如直径14mm或16mm；4–5颗，优先5颗。这些球只需要被动捕识别，不需要RGB模型识别，不必为首次试采先购买特殊规格。

**贴哪里**：与 `torso_link`（机器人躯干坐标系）固定连接的胸部刚性结构，或牢固固定的轻型刚性支架。不要贴在手臂/肩关节、骨盆、线缆、软垫、松动外壳或会晃动的支架上。相机与整组marker必须相对固定；“贴在胸前”不自动等于可靠。

**怎样排**：分散、不对称、有适当前后错层，不共线、不做规整正方形。下图只是布局示意，不是实机精确安装图：

```text
          胸部正面
      ● A                 ● B
                ● E
              （略向前）
         ● C          ● D
    各点间距不要完全相同
```

在安全、刚性和可见性允许时，整组覆盖范围可从约15–25cm、相邻点约5–10cm起步；某点可用牢固支座向前错层约2–4cm。**这些是试采起步建议，不是硬性尺寸或厂家保证参数。** 最终确认多台动捕相机同时看得到足够点，亮斑不合并、跟踪稳定、不会被碰掉。

Motar的原则是三点不共线、四点不共面；数学上三个不共线对应点能确定姿态，实际有遮挡所以建议多一两颗。已有可靠正式胸部刚体就沿用，不擅自重贴、删除重建或改变原点/朝向。

## 第一步：准备设备，选球，确认能录

### 1.1 固定安装，留好设置记录

**采什么**：安装状态、软件设置、相机内参和正在使用的配置。

**怎么做**：

1. 请管理员确认场地状态。先保存工程备份，请其确认采集期间不发生自动更新场地标定的操作；不要清除已有标定。
2. D435i使用最终支架，锁紧后拍照。已有可靠胸部刚体就沿用，记下软件中的名字，例如 `chest_R`，**不要为配合示例改名重建**。
3. 没有胸部刚体时请管理员协助建立。小球建议4–5颗，分散、非对称、有适当前后错层；尺寸和安装建议见本文件上方“胸部marker怎么选、贴哪里、怎样排列”。创建后不再移动marker、不改刚体原点或朝向。
4. 保存实际相机配置和 `CameraInfo`（相机信息，包含内参、畸变、分辨率等）。记录分辨率、帧率、曝光、发射器、深度滤波/对齐方式和 `depth units`（原始深度数值换算成米的倍率）。
5. 记录检测程序实际加载的配置、目标类别、球半径，以及输出是否已经补偿半径。示例配置里的数字不是你的实测值。

**为什么**：相机与胸部刚体相对位置改变就要重标；内参正确但分辨率、坐标系或补偿状态用错，也会得到错误结果。

**失败处理**：刚体松动、质量差或名字不清，先请管理员处理；不知道某项配置就记“未知”，不要猜。无法固定安装时不扩大采集。

### 1.2 动捕短检查：字段、单位、缺测一次确认

首次建议在**测试夹具**上完成，别折腾正式机器人资产。以下短片段可在同一准备录制中分段做，但必须标注动作区间。

| 动作 | 具体操作 | 你要确认什么 | 保存什么 |
|---|---|---|---|
| 静止约30秒（旧编号S1） | 测试刚体旁放一颗独立小球，两者不动，小球不要加入刚体 | 导出后同时有刚体位置/四元数、独立散点、帧时间 | `prepare_static`原录制、CSV、布局照片 |
| 已知位移（S2） | 请管理员指出实际世界轴；独立小球沿三个已知方向分别移动约200mm；起点、终点各停5秒，有条件再返回起点 | 不是把mm当m；轴方向、缩放和位移长度可解释 | 尺测长度、方向照片、动作区间和CSV |
| 遮挡恢复（S3） | 小球不动，先可见5秒、遮约2秒、恢复5秒，重复；另遮测试刚体使其短暂丢失后恢复 | 空值/0/NaN（无有效数值）如何表示；ID是否变；是否保持旧位置或预测 | 遮挡时段日志/视频、CSV |

遮挡只遮测试对象，不碰场地相机和正式资产。尺测用于检查量级，不用于宣称毫米级精度。若遮挡未造成丢失，写“未造成丢失”，不编造缺测样例。

**动捕录制和CSV导出这样做**：

1. 在Motar录制区设目录与片段名 → 开始录制 → 完成动作 → 停止。
2. 工程管理中找到片段 → 右键导出CSV（逗号分隔表格文件）。
3. 勾选**实测散点和刚体**；打开表头；缩放设1；建议明确选mm；使用原录制帧率、完整区间；记录绝对坐标、时码和坐标转换选项。
4. 请管理员说明世界轴。不要看到“World（世界）”就认定Z轴向上。某选项没有就拍照注明，不硬改。
5. 不做填补、平滑、抽帧或一键优化；不用Excel另存原CSV。保留软件原录制及直接导出文件。
6. 四元数通常是 `X/Y/Z/W` 四列，用来表示朝向，不是四个角度；当前解析工具不支持把欧拉角输出直接当四元数读。

**失败处理**：只有刚体没有散点，先查导出勾选项；不能用资产点补位。遮挡仍输出旧值，记录它，不当新测量。静止抖动明显（例如超过约2mm）时记录问题、找管理员排查；这不是独立的设备精度判决线。

### 1.3 选共同靶球：两边都能测，而且测同一球心

**采什么**：候选球尺寸、材质、两侧共同可见性，以及球心对应依据。

**怎么做**：

1. 编号 `target_01`、`target_02`等；拍完整球和底座，至少沿三个方向量直径。记录是整球还是半球、表面材料、支撑方式。
2. 每颗球在实际工作区近、中、远各停约10秒，动捕和相机同时录。距离按部署空间选，不强制1–4米。
3. 看RGB（彩色图）是否识别，`mask`（分割掩码，即程序标出的球区域）是否覆盖球、是否碰图像边缘。
4. 打开**数值深度**，确认球区域不是空洞或主要读到背景。彩色深度预览和截图不能代替原始数值。
5. 看动捕是否有稳定的对应散点、是否多出假点或频繁掉点。
6. 尽量保持球心不动，转动球的表面/接缝方向，再停稳。若支撑使球心也移动，照实记，不把所有变化都算传感器偏差。
7. 请管理员/厂家说明该尺寸球的动捕位置如何对应几何球心，或记录可核查的几何依据。稳定显示一个点，只能证明可跟踪，不能独立证明球心绝对准确。

**为什么**：小标准marker能被测量，不代表苹果大小反光球也适用；反光材料可能破坏RGB外观或造成深度空洞。

**最容易犯的错**：把一颗14mm小marker贴在大球表面，直接当大球中心。它们不是同一个点，偏移会随大球旋转而改变；不能随意减半径或让外参吸收。

**失败处理**：没有双方都能测、且同球心有依据的球，先停在筛球；保留问题样本，不正式采几百点。不默认切换红外/双目路线，也不临时增加未知球心偏移参数。

### 1.4 相机试录后立即回看，别等离场才发现没录到

本次观测链路是：

```text
彩色图 → 找出球的mask → 提取对应深度
→ 相机坐标中的表面位置或已补偿球心
```

**至少保存**：RGB、对齐到RGB的数值深度、CameraInfo、对应mask/图像时间，以及实际配置。能保存时另留原生深度和深度相机到彩色相机的内部外参。

- `aligned depth`（对齐深度）让深度像素对应彩色图；仍要确认深度数值是彩色光学系的z值，不只是把原深度z搬到彩色像素。
- `frame`（坐标系）应对应实际彩色光学系，常见名 `camera_color_optical_frame`，轴向是x右/y下/z前。
- 已有世界点使用 `TF`（坐标变换信息）里的未标定外参，**只能作诊断，不能当独立相机标定点**。保存变换前相机位置，或原始输入供离线重建。
- mask程序可能依赖TF才能正常输出；话题有名字不等于有消息。无法输出就记阻塞原因，不伪造TF冒充成功。

若现场已运行ROS 2（机器人通信框架），可用只读查询：

```bash
ros2 node list
ros2 topic list -t
# 仅当实际节点名确实为此名称时使用；否则替换为现场名称
ros2 param get /target_perception_node config_path
```

常见话题（数据通道）如下，**先核对现场名称/前缀，不照抄成保证可用的录制命令**：

| 话题示例 | 保存内容 | 用途 |
|---|---|---|
| `/camera/color/image_raw` | 彩色图 | 找球 |
| `/camera/aligned_depth_to_color/image_raw` | 对齐数值深度 | 算三维点 |
| `/camera/color/camera_info` | 内参等相机信息 | 解释像素与深度 |
| `/perception/target_mask` | 球的分割掩码 | 选球区域的深度 |
| `/perception/target_overlay_source` | 与检测相关的源图/时间，以实际消息为准 | 核对mask对应哪帧 |
| `/camera/depth/image_rect_raw` | 原生深度，支持时保留 | 排查相机内部注册几何 |
| `/perception/target_point_world` | 旧程序世界点 | 仅诊断，不参与独立点对 |
| `/tf`、`/tf_static` | 现有坐标变换 | 记录来源，不当外参真值 |

用已有工具录10秒，然后打开文件，检查消息数量、时间、mask和有效深度。如果收不到消息，请熟悉ROS的人核对 `QoS`（消息通信设置）。若运行的是非ROS程序，保存真实启动方式和它的录制结果，不硬套ros2命令。

**第一步结束条件**：安装固定；至少有一份可解释的动捕样本；球在双方可见；相机真实数值输入已录到。共心未知可保留诊断样本，但不要扩大正式采集。相机不可用时可以只带回动捕试录，必须注明“缺相机数据”，不能称完成了两侧采集。

## 第二步：采集编号静态位置

### 2.1 第一次先采15点，不先采几百点

**采什么**：同一球在不同位置的相机观测、动捕球心和胸部刚体位姿。建议3个距离层，每层5个位置，总计15点（12–20点亦可）。

```text
每个距离层的5个位置，示意而非精确坐标：
             上
             ●
     左 ●    ● 中    ● 右
             ●
             下
```

近、中、远要有实际距离差；左右高低在两套设备共同可见区，不贴图像边缘，不让手和支撑挡球。机器人、相机、胸部marker保持不动，**只移动靶球**。

### 2.2 每个位置照这个顺序做

1. 两侧开始录制；先留一个约10秒静止段，方便之后核验录制顺序。
2. 操作者报编号，例如 `sample_01`（静态位置编号），记录者在日志里写下编号及距离层/方向。
3. 将球放好、松手、等支撑稳定，停3–5秒。不要边拿着抖边认为“已经静止”。
4. 记录动捕和相机**各自录制时间**中的稳定区间，或可唯一找到该区间的片段编号。两台设备时间零点不同，不能把一侧时间直接抄到另一侧。
5. 观察两侧是否有效；掉点/漏mask就记异常，重复该位置时用新编号或明确标注重采版本，不覆盖旧记录。
6. 换下一个位置。结束时再留一个约10秒静止段，停止两侧录制。

位置日志：下面是15点安排，不是已完成记录。编号不是散点ID；稳定区间应取停稳后的内部有效片段，至少约0.3秒，不能包含拿球移动过程。

| 位置编号 | 距离层/方向 | 动捕片段及稳定时间段 | 相机片段及稳定时间段 | 是否有效/异常/重采编号 |

### 2.3 torso对齐什么时候采

第一次没有确认CAD（机器人结构模型）和安装几何，可以暂缓。最终若要把结果用于 `torso_link`（机器人躯干坐标系），需要5–8个已知特征的**marker球心**坐标及动捕测量，不能用外壳表面点直接替代。

**特征marker安装注意**：可以用标准小球，在CAD与实机一致、能精确定位的孔位/螺钉/外壳特征上分散布置，尽量有三维展布。记录的是球心，不是外壳贴点：

```text
marker球心 ≈ 表面定位点 + 安装方向上的（底座高度 + marker半径）
```

仅在安装方向和几何已核实时才能这样计算，还要考虑偏心、模型单位/缩放和固定变换。特征marker不要并入胸部刚体资产来冒充独立测量；没有具体实机结构信息，不直接指定必须贴哪个孔。

本次特征采集安排：____；暂缓原因/需补资料：____。

这不是第四个上机步骤：确认了特征后，可在本步骤内另录明确命名的特征静态段；还没确认就另约采集。没有这部分数据只能求 `T_R_C`，不能冒充得到 `T_torso_C`。详细几何见 [核心流程](机器人动捕标定_核心流程.md)。

## 第三步：导出，核对，备份

**采什么**：把前两步数据原样带回来，并能根据日志找出每个位置。

**怎么做**：

1. 按第一步的设置导出动捕CSV，保留原工程/录制。用文本查看器确认表头、刚体位姿、实测散点与帧时间存在，不用Excel另存。
2. 打开相机录制，随机查看近、中、远和末尾位置：RGB、数值深度、mask和CameraInfo是否真的保存。只有视频或截图不够。
3. 对日志逐行数一遍；例如15个位置，其中2个失败，就明确写13个有效，而不是为了凑15强配。
4. 给未知项写明原因；记录所有调过的设置，请管理员恢复正式场地设置。
5. 按下列目录整理，复制到第二个存储位置。目录中的会话名自行替换，例如 `trial_2026_01`。

```text
data/raw/<session_id>/
├── mocap/   # 原工程/录制、直接导出的CSV
├── camera/  # RGB、数值深度、mask、CameraInfo、实际配置
└── notes/   # 布置照片、导出截图、球尺寸、位置配对、异常
```

可用 [文件记录模板](../data/templates/trial_manifest.example.csv) 和 [候选靶球模板](../data/templates/target_inventory.example.csv)，不方便当场填CSV时先用纸或普通日志记，回去再整理。模板只是字段，不是已成功记录。

## 离线处理：回去以后做，不占上机三步

将原始数据交给离线工具：解析动捕 → 每帧转换到胸部刚体系后平均 → 重建相机球心 → 按编号配对 → 求候选外参并看报告。命令见 [根README](../README.md)，工具不直接解包任意ROS录制包，也不自动生成检测mask。

第一轮重点看单位、坐标、共心、重复补偿、配对和随距离变化的误差。真实CSV首次可能与已实现表头适配不同，应修适配器，不改原CSV。没有实录就不能确认兼容，没有独立验证就不称正式标定成功。
