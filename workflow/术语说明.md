# 动捕标定术语说明：遇到英文时查这里

> 这是阅读辅助，不是额外操作流程。现场不需要先背完这些词；先看各文档中的中文解释，遇到不认识的名称再查本表。

## 一、设备、球和坐标

| 名称 | 中文解释 | 在本项目中要注意什么 |
|---|---|---|
| MoCap / Motion Capture | 动作捕捉，简称动捕；多台相机测反光点的位置 | 本项目使用 FZMotion，不是 D435i 自己测出来的数据 |
| FZMotion / Motar | 动捕系统的软件名称/版本名称 | 录制、创建刚体和导出 CSV 都在这个软件里操作 |
| marker / Marker | 反光标记球；CSV 中的 `Marker` 类型指实测散点 | 散点只给点的位置，不等于物体完整朝向 |
| Rigid Body | 刚体；固定在同一物体上的一组标记点 | 点间结构不变，软件可计算位置和朝向 |
| RigidBodyMarker / asset point | 刚体资产点；属于软件刚体定义的点 | 可能由模板/刚体位姿推算；本主线不拿它代替独立实测散点 |
| target | 目标物或标定靶球 | 胸部小 marker 和共同靶球不是同一种用途 |
| torso / `torso_link` | 躯干；机器人模型中躯干坐标系的名称 | 动捕胸部刚体系 `R` 不自动等于它 |
| pelvis | 骨盆；机器人模型中腰部下方的坐标系 | 与 torso 之间有腰关节，不能直接当成固定的同一坐标系 |
| frame / coordinate frame | 坐标系；定义原点和三根轴 | 英文 frame 也可指“一帧图像”，必须按上下文区分 |
| color optical frame | 彩色相机光学坐标系，通常 x 向右、y 向下、z 向前 | 本次 RGB-D 观测使用它；实际名字常为 `camera_color_optical_frame` |
| world / `local_world` | 世界坐标系/程序自定义的局部世界坐标系 | 程序的世界系不一定等于动捕世界系，不凭名字当成同一个 |
| pose | 位姿：位置加朝向 | 刚体位姿不是单个球心位置 |
| quaternion / xyzw | 四元数；用四个数表示旋转，xyzw 是存储顺序 | 不是四个角度；不要用平均四个分量的方法直接平均旋转 |
| Z-up / Y-up | Z轴/Y轴指向上方的坐标约定 | “World”只表示世界系，不能证明哪根轴向上 |
| SE(3) | 三维刚体变换：旋转加平移，不包含缩放 | 本项目的外参矩阵属于这种变换 |
| `T_A_B` | 把 B 系的点变到 A 系的变换 | 例如 `T_R_C` 是相机 C → 动捕胸部刚体系 R |
| inverse / `inverse(T)` | 取逆；把变换方向反过来 | `inverse(T_W_R)` 把世界系点变到 R 系 |
| CAD | 计算机辅助设计；此处指机器人三维结构/尺寸模型 | 需要与实机装配一致，不能把外壳表面点直接当 marker 球心 |
| URDF | 机器人描述文件，记录部件和关节的连接/坐标关系 | `link` 是部件坐标系；`visual origin` 是模型外观相对部件的偏移 |
| TF / `/tf` / `/tf_static` | ROS 中的坐标变换信息；后两者是相关数据通道 | 现有未标定外参不能当标定真值；只录这些信息不能替代相机原始观测 |

## 二、相机看到了什么

| 名称 | 中文解释 | 在本项目中要注意什么 |
|---|---|---|
| RGB | 红绿蓝三通道，即彩色图像 | 检测程序从彩色图里找到球 |
| depth | 深度图；像素数值表示深度，不是普通照片亮度 | 不仅要保存可视化截图，还要保存数值数据 |
| RGB-D | 彩色图加深度图 | 本项目的检测主线，不要求先开发红外检测 |
| IR | 红外图像 | D435i深度和动捕补光可能互扰，但IR不是本轮必采检测主线 |
| mask / segmentation mask | 分割掩码：指出图像中哪些像素属于球 | 检查轮廓是否盖住真实球；必须对应同一帧图像 |
| centroid | 质心；此处是 mask 像素的平均位置 | 图像质心不自动等于准确的三维球心投影 |
| aligned depth / depth-to-color | 对齐到彩色图像的深度：让深度与彩色像素对应 | “像素位置对齐”不保证保存的深度数值已经是彩色相机 z 值 |
| color z / depth z | 在彩色/深度光学坐标系中沿 z 轴量到的距离 | 两个光心不同；不能只换名字就当同一个值 |
| CameraInfo | 相机信息消息，通常含内参、畸变、分辨率等 | 内参已标定；保存本次实际 K/D，不抄示例焦距 |
| K / D | 相机内参矩阵/畸变参数 | 与实际使用的分辨率和图像处理方式对应 |
| intrinsics / extrinsics | 内参/外参：相机内部投影参数/不同坐标系之间的位置与朝向 | 这次不重标内参；外参要在动捕中重新求解 |
| depth units / `depth_unit` | 原始深度数值换算成米的倍率 | 若每单位是1mm则倍率为0.001，但必须读实际配置，不能凭示例假定 |
| surface / center | 球的可见表面/几何球心 | 深度常测到表面；程序可能已经加过球半径，不能重复加 |
| radius compensation | 半径补偿；按观测模型把表面位置换到球心 | 不等于把表面小 marker 换成大球球心；后者还有未知方向的偏移 |
| deprojection | 反投影；由像素、深度和内参算三维位置 | 必须使用对应光学坐标系及正确深度定义 |
| detector / pipeline | 检测器/处理链路；从图像找到球并算位置的程序 | 既有程序不是完整采集器；能看到画面不代表数据已经保存 |
| foreground percentile / MAD | 前景分位筛选/中位数绝对偏差；筛除部分背景和异常深度的方法 | 是代码的深度筛选方式，不要求新手现场计算 |

## 三、文件、录制和命令

| 名称 | 中文解释 | 在本项目中要注意什么 |
|---|---|---|
| CSV | 逗号分隔的表格文件 | 动捕原始CSV可能有多层表头；不要用Excel另存改变格式 |
| JSON / YAML | 保存配置的文本格式 | 记录实际启动的文件；`null`表示未知/未填写，不是0 |
| NPZ | NumPy数组压缩文件，可存深度和mask等数值数组 | 离线工具能读，但不会自动把任意录制转换成这个格式 |
| ROS 2 | 机器人软件通信框架 | `ros2`命令要在已经正确加载ROS环境的终端中执行 |
| node / topic | 节点（运行程序）/话题（数据通道） | `ros2 topic list`列出名字；不证明有有效消息或已录制 |
| namespace | 命名空间；名称前面的路径前缀 | 实际话题可能与示例不同，录制前按现场列表核对 |
| QoS | 通信服务质量设置，例如消息可靠性 | 设置不匹配可能看得到话题却收不到消息；遇到时找熟悉ROS的人检查 |
| rosbag / bag | ROS录制包；保存多路消息的文件集 | 本工作区不直接解包任意bag，必须由已有工具导出所需观测 |
| native | 非ROS的原生程序部署方式 | 如果不是ROS运行，不照搬ros2录制命令 |
| timestamp / clock | 时间戳/时钟来源 | 两台设备的起始时间可能不同，静态段仍需分别记录和配对 |
| sample_id / session_id | 一个静态位置的编号/一次采集会话的编号 | 用于防止错配；不是散点ID，散点ID可能变化 |
| metadata / provenance | 元数据/来源记录：单位、坐标、设置、输入文件等 | 用来解释一份数据到底是什么，不是额外的测量值 |
| hash / SHA-256 | 文件内容摘要，可识别文件是否改变 | 软件记录即可，不要求操作者手工算 |
| CLI / preflight | 命令行接口/运行前配置检查 | 检查通过不代表实机精度通过 |
| NaN / Inf | 无有效数值/无穷大 | 不当作有效位置，不填0冒充缺失点 |

## 四、求解和结果

| 名称 | 中文解释 | 在本项目中要注意什么 |
|---|---|---|
| Kabsch | 用两组对应三维点求旋转和平移的算法 | 本工具不在外参中估计缩放 |
| Huber | 鲁棒损失：减少少量异常点对拟合的影响 | 不能修复系统性的球心错位、错配或单位错误 |
| residual | 残差：预测值与测量值之差 | 看距离/区域是否有规律性偏差，不能只看总平均 |
| covariance / sigma | 协方差/标准差：描述测量不确定程度 | 深度方向常比横向更吵，软件据此加权 |
| train / validation / holdout | 求解数据/验证数据/预留未参与求解的数据 | 必须按独立位置划分，不把同位置的几帧拆给两边 |
| RMSE | 均方根误差，概括一批位置误差的大小 | 初始目标3D RMSE<2cm；不是相机实测精度保证 |
| P95 | 95%分位误差；约95%的误差不超过该数值 | 与RMSE一起看，避免少量大误差被平均掩盖 |
| split consistency | 分半一致性；两部分训练点各求一次结果再比较 | 只能看稳定性，不能独立证明绝对准确度 |
| synthetic / demo | 合成数据/演示 | 软件自测用，不是真实动捕采集 |
| `synthetic_pass` | 合成数据测试通过 | 不允许当成机器人可部署标定 |
| `unverified` | 未完成实机确认的候选结果 | 可看报告，但不称“正式外参” |
| `validation_failed` | 验证未通过 | 保留报告，排查或补采，不正式发布 |
| `hardware_accepted` | 工具记录的实机验收通过状态 | 需真实数据、软件判定和现场确认齐备；不能凭手填字段冒充 |
| attestation | 对现场事实的明确确认记录 | 工具要求四项真正确认；没有现场依据不要填true |
| DDL | 截止日期 | 当前采用一次软件开发、少量试采与必要的留出验收，不逐小项审批 |
