# 动捕定位与机械臂精准抓球：mpc-real 实施路线

> 目标：用动捕测得真实球心，接入关联仓库的机械臂 MPC，逐步实现静态精准到位与闭合抓球。
> 核查对象：关联仓库 `https://github.com/sysu-3d-embodied/unitree-g1-dynamic-catch.git` 的实际分支 `deploy/non-policy/mpc-real`，主仓库 commit `3c9b35881edac69338987fe78da6d1f10ffaeaed`；模型资产子仓库 commit `5a564c36e35e073680bc90f66b44db4abdb7d011`。
> 以下源码结论以该版本为准；更新部署版本后须重新核对。**本文是实施方案，不是已完成的实时接入或实机验收记录。**

## 1. 总体路线与当前边界

建议先用动捕直接提供目标，暂时绕过 D435i：先验证机械臂能否准确到达，再加入手指闭合，最后考虑相机替代与动态接球。

```text
真实球心
  → 动捕坐标转机器人坐标
  → 球心转实际抓取工具目标
  → MPC 控制手臂到位
  → 独立实测到位确认
  → 手指受限闭合与抓持验证
```

**动捕定位精度不等于最终抓取精度。** 胸部对齐、工具偏移、运动学模型、关节跟踪和时延都可能使手偏离球。

| 项目 | 核查版本的实现 | 对实施的影响 |
|---|---|---|
| 目标输入 | `geometry_msgs/msg/PointStamped`，默认 `/perception/target_point_world` | 可由动捕适配节点替代相机输入 |
| 输入坐标 | `local_world`，单位米 | 不能直接填写动捕世界坐标 |
| MPC tool | `right_palm_center` | 不是自动标定好的抓球中心 |
| 姿态约束 | ready 时锁存掌心参考法向；tool `+X` 为外法向；只约束终点法向，绕法向旋转自由 | 不保证手指朝向或整个接近过程姿态 |
| 普通执行 | `committed`，每轮约 2 秒，之后按实测状态重新规划 | 先用于静态球，不是高频追逐快速运动球 |
| 手部控制 | 核查到的通用 `HandController` 只有 `Open/Hold` | 仍需实现匹配实际硬件的闭合抓取流程 |
| 碰撞检查 | 当前 worker 配置关闭自碰撞检查、未加载碰撞球 | 不能默认具备自身、桌面或球架避碰能力 |

worker 的 `goal_seed.position_tolerance_m=0.005` 是模型规划终点容差，**不证明实机已达到 5 mm**。关联仓库部署文档也明确实机跟踪尚未完整验收。

本仓库现有软件以静态离线标定为主，不包含实时 FZMotion 节点、手臂控制或闭合抓取。已有相机外参流程见 [机器人动捕标定核心流程](机器人动捕标定_核心流程.md)。本方案扩展任务范围，不改变该流程原有边界。

## 2. 测到真正的球心

### 2.1 被抓小球本身就是反光整球

若 FZMotion 重建的是这颗球的中心，且现场确认观测定义，可直接使用动捕世界系球心 `p_W_ball`。

先做静止录制和已知位移检查，确认单位、轴方向、重复性、缺测和遮挡恢复。精度以实测报告为准，不直接假设毫米级。

### 2.2 普通球表面贴单个反光 marker

**marker 中心不是被抓球的中心。** 球转动时，偏移方向也会变化；只有一个 marker 通常无法恢复该方向，不能沿固定世界轴减去一个半径。

建议建立轻量、刚性、不对称的球 marker 结构：至少 3 个非共线点，实际增加冗余以覆盖遮挡，创建球刚体 `B`。通过可靠几何测量、夹具或多姿态标定，得到球心在刚体系中的固定坐标 `c_B`：

```text
p_W_ball(t) = T_W_B(t) · [c_B; 1]
```

marker 支架不能妨碍手指闭合；用于动态接球时还要考虑其对质量、惯性和接触形状的影响。

## 3. 动捕球心转到控制器坐标

### 3.1 坐标与变换约定

沿用本仓库约定：`T_A_B` 表示将 B 系坐标变成 A 系。点变换采用齐次坐标，内部单位米。

| 符号 | 坐标系 |
|---|---|
| W | 动捕世界系 |
| R | 胸部动捕刚体系 |
| T | 机器人 `torso_link` |
| L | 控制器 `local_world` |
| B | 球 marker 刚体系 |
| P | MPC tool：`right_palm_center` |
| G | 实际抓取中心 |

### 3.2 推荐先使用胸部相对位置链

使用同一动捕帧的球心与胸部位姿：

```text
p_R_ball(t) = inverse(T_W_R(t)) · p_W_ball(t)
p_T_ball(t) = T_torso_R · p_R_ball(t)
```

`T_torso_R` 必须标定，不能因刚体名称相似就设为单位矩阵。本仓库已有 `src/dc_calib/alignment/torso.py`，用明确对应的结构特征球心求解这段变换。按现有核心流程准备约 5–8 个分散且可靠测量的特征，并做独立检查；没有可靠对应就不能宣称这段已完成。

再用控制器自己的基座状态和实测腰部关节得到：

```text
T_L_torso_controller(t)
  = T_L_pelvis_controller(t) · T_pelvis_torso(q_waist_measured(t))

p_L_ball(t)
  = T_L_torso_controller(t) · T_torso_R
    · inverse(T_W_R(t)) · p_W_ball(t)
```

必须使用与控制器一致的模型、基座姿态及实测腰部角度，并按测量时间对齐。不要用下发关节命令替代实测值，不要随意拼接最新但不同步的状态。

### 3.3 为什么不能直接使用动捕世界坐标

核查版本的 `unitree_zmq_bridge_node.cc` 构造机器人状态时：

- 基座平移来自 profile 的固定 `base_position_world_m`；
- 基座旋转来自 IMU；
- 掌心位置由实测腰部、右臂关节进行 FK，再组合到该世界系。

因此当前 `local_world` 不是动捕世界系，也不是完整的动捕基座定位结果。仅把 `p_W_ball` 的 `frame_id` 改成 `local_world` 会制造坐标错误。

上述相对胸部链可优先避免全局世界系配准。以后若改用动捕提供基座定位，必须同步更新控制器状态链及相应时钟、姿态约定，不能只改球坐标或 RViz 的 TF。

## 4. 标定实际抓取中心与工具偏移

核查版本的 `right_palm_center` 是依据手掌部件体积质心定义的虚拟点，不一定是掌面中心，更不一定是手指闭合时球心所在的位置。

设 `d_PG` 为抓取中心 G 在 tool P 系中的固定坐标，则：

```text
p_L_G = p_L_P + R_L_P · d_PG
p_L_P_target = p_L_ball - R_L_P_target · d_PG
```

送入当前 MPC 的应是 `p_L_P_target`，而不是未经确认的球心。球尺寸和手指构型可能改变实际抓取几何，需明确适用范围；不能重复补偿半径或把任意半径直接当成工具偏移。

### 实测建议

1. 在手背或手腕的刚性部位安装动捕刚体 H，不装在会变形的指尖皮肤上。
2. 用夹具或可靠几何测量确定 H 与工具、掌面、抓取中心的关系。
3. 采多个安全、分散的静态手臂姿态，同时记录动捕与实测关节角。
4. 比较真实手部位置与模型 FK，先检查工具固定偏移，再判断关节零位或结构误差。

不要把所有姿态相关误差塞进一个固定平移；多参数运动学标定需要独立数据与可辨识性检查。

当前模式只约束掌心法向，绕法向旋转自由。如果 `d_PG` 有明显侧向分量，偏移方向会随手指朝向改变，需要明确完整姿态目标、在模型中统一定义抓取 tool，或其他经过验证的处理。不能只按固定世界方向补偿。

若修改 tool 定义，应同步核对 worker 模型、bridge 的 FK、到位判据和可视化，避免规划和实测仍使用不同中心。

## 5. 实时接入方案与必要安全修改

### 5.1 建议节点链路

以下节点与话题为拟新增方案，并非本仓库已实现接口：

```text
FZMotion 实时数据
  ├─ 球/球刚体
  ├─ 胸部刚体
  └─ 手部刚体：独立误差测量
          ↓
动捕适配节点
  ├─ 球心恢复
  ├─ 有效性、乱序、跳变、超时检查
  ├─ 时间对齐及控制器状态读取
  ├─ 转到控制器 local_world
  └─ 球心转掌心工具目标
          ↓
/mocap/palm_target_world（PointStamped）
          ↓
现有 mujoco_deploy_node → MPC → Unitree bridge → 右臂
```

现有 `unitree_zmq_deploy.launch.py` 支持目标话题参数，可使用：

```text
target_topic:=/mocap/palm_target_world
prediction_path_required:=false
```

首次只读联调保持 `enable_position_commands:=false`，关闭相机目标输入，保证只有一个有效目标源。核对移动方向、坐标变换和工具补偿后，再按关联仓库部署指南，在吊架/支撑保护和急停操作者到位时分阶段允许运动。

### 5.2 单点缓存必须增加失效门控

核查版本的 `mujoco_deploy_node.cc` 中：

- `ReceiveTarget` 检查 frame 与有限数值，并缓存目标；
- `TargetMeasurement` 使用控制循环提供的时间构造测量，未完整保留原始观测新鲜度语义。

因此**动捕断流后仅停止发布，不保证控制器停止追踪旧目标**。不能依赖话题消失自然停止。

实施前需要在适配节点和控制器目标入口补齐：

- 原始测量时间、接收时间及明确的时钟映射；
- 球与胸部刚体同时有效，机器人状态时间匹配；
- 重复/乱序、超时、非有限数值、异常跳变拒绝；
- 目标失效后撤销缓存和规划资格，并进入已验证的安全保持流程；
- 在无硬件输出条件下测试断流、遮挡、时钟偏差和恢复，不允许自动绕过解锁门控。

具体超时门槛由实际帧率、延迟与任务风险确定，不照抄未测值。跨设备不能直接相减不同来源的时间戳。

### 5.3 SDK 兼容性仍需确认

LuMoSDK 手册说明可接收散点、刚体及时间戳，但所给示例偏 Windows，Python 示例也有版本要求。Ubuntu 环境需确认实际 SDK、支持平台、Python 版本和广播协议；必要时使用受支持的接收主机转发规范化数据。

本仓库的离线 CSV 支持不等于实时 SDK 接入已完成。

## 6. 分阶段实验与验收

### 阶段 A：静态定位，不运动

球放在多个独立位置，覆盖近/远、左/右与不同高度：

- 检查球心恢复与静止重复性；
- 独立验证 `T_torso_R`，记录单位、坐标轴与安装版本；
- 改变机器人身体姿态时，检查相对球位置是否正确；
- 测量帧率、端到端延迟、遮挡和断流行为。

### 阶段 B：手臂到位，不闭手

球固定在不妨碍运动的支架上，先到安全预接近点，再低速靠近。用动捕独立测量实际抓取中心：

```text
e_reach = p_L_G_mocap - p_L_ball
```

若手和球可在同一动捕帧观测，优先同时记录动捕世界系中的相对误差，避免诊断过度依赖待验证的机器人坐标链。

| 比较项 | 主要排查对象 |
|---|---|
| 动捕实际手部位姿 vs 实测关节 FK | 工具偏移、模型、关节零位 |
| 实测关节 FK vs 目标 | 规划与实际关节跟踪 |
| 实际抓取中心 vs 球心 | 最终几何到位误差 |
| 下发关节 vs 实测关节 | 执行误差、限幅和状态时延 |

不要只看 RViz 模型到位，它通常还是模型 FK，不是独立实测。记录每点误差、RMSE、P95、最大值、姿态和重复实验结果；用于调参的位置不能继续称作独立验证。

先把厘米级作为链路排错目标，再按球尺寸与手部容错范围收紧到例如 5–10 mm。数值是待确认的工程目标，不是现有系统保证；相机外参流程的 2 cm 起点也不能直接作为精密抓球验收标准。

### 阶段 C：闭合抓取

新增任务状态机：

```text
张手 → 到预抓取位置 → 低速接近
     → 实测位置/速度持续稳定
     → 手指受限闭合
     → 检查接触或抓持状态
     → 小幅提起验证
```

需匹配实际手部硬件，补闭合命令、指关节限位、力度/电流等保护和抓持确认。`MPC solve success` 或 2 秒轨迹完成都不能直接作为闭手条件。

达到位置时仍需检查速度、姿态、球/手观测有效性、碰撞和接近空间；失败应走明确的退出/保持流程，不继续盲目闭合。

### 阶段 D：相机替代与动态接球

静态动捕链稳定后，再使用本仓库标定 D435i，让相机作为目标源、动捕作为独立真值，区分视觉误差和手臂误差。

快速动态接球另需时间标定、球速度/轨迹估计、未来拦截点、可达时间与实时重规划验收。当前普通 2 秒 committed 执行不是高频移动目标跟踪；不能仅提高动捕发布频率就宣称已支持动态接球，也不能未经验证直接套用其他 profile。

## 8. 待办与完成定义

以下项目无真实记录时不勾选：

- [ ] 确认球心观测方式，必要时完成球刚体到球心的偏移标定。
- [ ] 完成 `T_torso_R` 与独立检查，冻结胸部安装和资产定义。
- [ ] 完成手部动捕夹具、真实抓取中心定义与模型 FK 对照。
- [ ] 实现实时适配、时钟映射、机器人状态对齐和目标失效门控。
- [ ] 只读验证输入坐标、单位、跳变、遮挡、断流及恢复。
- [ ] 在保护条件下完成多位置静态到位实验并保存独立误差报告。
- [ ] 实现受限闭合、抓持确认和失败处理，完成静态抓取重复实验。
- [ ] 记录部署 commit、模型/配置、球尺寸、延迟、日志、操作者与安全条件。

**优先级：确认真实球心 → 对齐机器人躯干 → 测真实抓取中心 → 动捕单点静态到位 → 受限闭合。**

不要先继续叠加相机标定或调 MPC 参数；先建立“真实球心—机器人躯干—真实抓取中心”的一致几何关系，并独立证明手确实到位。
