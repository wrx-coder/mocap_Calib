# 动捕数据层（MoCap Data Layer）设计规格 v1

> **范围**：把 FZMotion 当作黑盒，只处理它的输出，把原始数据变成下游（`T_torso_R` 对齐、MVP 外参标定、δt、静态抓取）需要的数据产品。**本层不做任何标定求解**。
> **上游依据**：`机器人动捕标定方案_v4.md`（§1.5、§4.3、§6.3、§7.5、§7.7）、`FZMotion动捕系统要点_v4对接.md`（§2、§5、§6）、`T_torso_R对齐与marker尺寸要求_1.md`。
> **实现方式**：由 Ubuntu 上的 agent 按本规格编码。本文只定架构、接口契约、方法和验收标准，不写代码。
> **前提**：目前还没有真实的 FZMotion 导出文件。因此 M0–M1 完全基于合成数据开发，M2 用第一次真实录制来校正所有未知项（§8）。

## 0. 速查

```
定位      : FZMotion 黑盒 → 统一数据模型 → 数据产品（文件 / 话题）。不含标定求解
分层      : L0 源适配器 → L1 统一数据模型 → L2 处理（纯函数）→ L3 数据产品 → L4 CLI / 报告
            核心库不依赖 ROS；ROS2 只出现在最外层薄壳
内部约定  : 单位 SI（m、s、rad）；右手系、Z 向上；四元数 xyzw、单位化、半球连续
            T_A_B 记号沿用 v4 §1.3；缺测用 NaN 加有效掩码，绝不用 0 填
数据产品  : P1 躯干特征点（R 系）      → §1.5 T_torso_R
            P2 静止球心样本（R 系）    → MVP T_R_C
            P3 连续轨迹（R 系 + 时间） → δt
            P4 在线刚体位姿（torso 系）→ 静态抓取
里程碑    : M0 模型 + CSV 解析 + 合成器 → M1 处理 + P1/P2 + 报告 → M2 首次真机录制，校正未知项
            → M3 ROS2 VRPN + P4 → M4 P3 / LuMoSDK
```

## 1. 边界：本层负责什么，不负责什么

| 负责 | 不负责（属于下游） |
|---|---|
| 解析 FZMotion 的 CSV / VRPN / LuMoSDK 输出 | 求 `T_torso_R`、`T_R_C`、`r`、`s`、`δt` |
| 统一单位、坐标轴、四元数和时间表示 | 相机侧的 IR 检测与 bag 解析 |
| 质量检查：缺测、跳变、刚体抖动、丢帧 | 动捕静止段与相机静止段的配对 |
| 静止段切分、散点身份关联、转到刚体系 R | 把 CAD 特征和 marker 对应起来 |
| 按契约输出数据产品，并附带完整的溯源元数据 | URDF 写回 |
| R 系点云的空间展布自检（v4 §7.5 的动捕侧预览） | 相机系下的可观性判据 |

**原则**：下游只读 L3 产品，从不直接读 FZMotion 文件。将来换动捕系统、换接口（CSV → LuMoSDK），只改 L0。

## 2. 分层架构与代码层次

### 2.1 分层

| 层 | 职责 | 依赖 | 可测性 |
|---|---|---|---|
| **L0 源适配器** | 只解析，不做几何：读入原始数值，打上“源约定”标签（单位、轴、时间基准） | 文件 / 网络 / ROS2 | 用合成文件和真机样例做黄金测试 |
| **L1 统一数据模型** | 规范化：单位换算、轴变换、四元数规范化、时间统一、缺测标记 | L0 | 往返测试 |
| **L2 处理** | 质量检查、静止段切分、散点关联、变到 R 系、段内聚合、展布自检 | L1、几何工具 | 纯函数；合成数据有真值 |
| **L3 数据产品** | 按契约写文件或发布话题，附带元数据 | L2 | 用 schema 校验 |
| **L4 工具** | CLI：`inspect` / `extract` / `report`；ROS2 节点薄壳 | L0–L3 | 冒烟测试 |

### 2.2 包结构（建议）

```
dc_mocap/                  核心库，纯 Python + numpy / scipy，不 import 任何 ROS 包
├── io/                    L0：fz_csv（P0）、vrpn_bag（P1）、lumo（P2，先留桩）
├── model/                 L1：Session、RigidTrack、MarkerTable、Segment 等数据结构；规范化
├── geom/                  SE(3) / 四元数 / 轴约定工具 —— 与标定代码共用，见 §2.3
├── process/               L2：quality、static_seg、associate、body_frame、aggregate、spread
├── products/              L3：各产品的写出器 + schema
├── sim/                   合成数据生成器（产出与 FZMotion 格式一致的 CSV）
├── cli/                   L4：inspect / extract / report
└── tests/
dc_mocap_ros/              ROS2 薄壳：VRPN 订阅 → 调 dc_mocap → 发布 P4；录 bag 的 launch
configs/                   会话配置 YAML（§6）
```

### 2.3 与标定代码的共享约定

`geom/` 是整个项目唯一的坐标变换工具来源，标定模块直接依赖它，不另写一份。它固定以下约定：

- `T_A_B` 把 B 系下的点变到 A 系；变量命名一律带两个坐标系名，如 `T_W_R`，禁止出现 `pose`、`T` 这类无系名的名字；
- 四元数内部统一为 xyzw，在 Eigen / ROS 的边界处显式转换；
- 旋转的插值与平均只在 SO(3) 上做（SLERP；平均用 chordal L2 或迭代 Karcher），不对欧拉角或四元数分量取算术平均。

## 3. L0：源适配器

### 3.1 FZMotion CSV（P0，首先实现）

**解析策略：由表头驱动，不写死列号。** 依据格式说明 V1.2：

| 内容 | 解析要点 |
|---|---|
| 标题行 1 | 键值对：DataName、FrameRate、StartTime、FrameCount、LengthUnits、CoordinateSpace。**全部进入 Session 元数据**，未知键也原样保留 |
| 标题行 2–5 | 资产类型（Rigid Body / RigidBodyMarker / Marker / Bone …）、名称、ID、量名（Rotation / Position / Speed …）、分量（X / Y / Z / W）。按这四层组合定位每一列 |
| 数据行 | 帧 ID、帧时间，然后是数据 |
| 刚体 | Rotation XYZW + Position XYZ，其余可选列（速度等）识别后丢弃，不报错 |
| 欧拉角导出 | **识别到就直接报错**，提示改用四元数重新导出 |
| 资产点 RigidBodyMarker | 解析出来但标记为 `provenance=asset_point`（可能是模板推算值）；默认不进入任何产品，见 §8 第 4 项 |
| 散点 Marker | 转为长表：（帧、marker_id、x、y、z）；ID 只当提示信息，不当身份 |
| 缺测表示 | 真实格式未知（空格？0？）。可配置；默认把空值和精确的 (0, 0, 0) 都视为缺测 |
| 人体 / 骨骼 | 本项目不需要，跳过 |

**源约定标签**：长度单位（取自 LengthUnits，默认 mm）、轴约定（取自会话配置，CSV 自身没写 Y_Up / Z_Up 时必须由配置给出，不允许猜）、时间基准（`StartTime` 是动捕主机的本地时钟，时区写在配置里）。

### 3.2 VRPN（P1，M3）

- 来源有两种：ROS2 VRPN 客户端的在线话题，或录好的 bag。适配器只读 bag 中的话题，不负责连接管理（连接交给 ROS2 节点）。
- 只有刚体。单位 m。时间戳为接收端时间（`use_server_time=False` 时），打标签 `clock=ubuntu_recv`。
- 轴约定同样由配置给出，必须与同一会话的 CSV 一致；M2 会验证两者相同（§8 第 6 项）。

### 3.3 LuMoSDK（P2，M4，先留桩）

接口按“帧流”定义：帧 ID、三种时间戳、散点、刚体。等厂家给出 Linux 库或 `.proto` 后再实现。数据结构与 CSV 适配器的输出完全相同，L1 以下不感知差异。

## 4. L1：统一数据模型

### 4.1 实体

| 实体 | 字段（概念层） | 说明 |
|---|---|---|
| **Session** | 会话 ID、源类型、源文件哈希、帧率、帧数、StartTime、源约定（单位 / 轴 / 时钟 / 时区）、资产文件哈希、配置哈希、代码版本、操作者备注 | 每个产品都带一份 |
| **RigidTrack** | 名称、源 ID、帧 ID[N]、`t_rel`[N]、`t_abs`[N]、`p_W`[N,3]（m）、`q_W`[N,4]（xyzw）、`valid`[N] | 位姿即 `T_W_<刚体>` |
| **MarkerTable** | 长表：帧 ID、`t_rel`、源 marker ID、`p_W`（m）；关联后增加 `track_id` 与 `label` | 每帧点数可变 |
| **Segment** | 段 ID、对象（轨迹 / 刚体）、起止帧、起止时间、帧数、段内统计量 | L2 产出 |
| **Clock** | 标签：`mocap_pc` / `ubuntu_recv` / `lumo_sync` / `hw_trigger` | 时间戳必须带时钟标签，跨时钟比较必须显式转换 |

### 4.2 规范化步骤（顺序固定）

1. **单位**：换成 m。
2. **轴**：源约定 → 内部 Z-up 右手系，变换矩阵由配置给出（例如 Y_Up → Z_Up 的固定旋转）。**行列式必须为 +1**，否则说明源坐标系是左手系，直接报错（例如误开了“UE4 格式”）。位置和姿态同时变换：位置左乘；姿态作基变换。
3. **四元数**：单位化（模长偏离 1 超过 1e-3 记为可疑帧）；沿时间做半球连续（与上一帧点积 < 0 就取反）。
4. **时间**：`t_rel` 取 CSV 的帧时间；用帧 ID 的连续性检测丢帧；`t_abs = StartTime + t_rel`，标签为 `mocap_pc`。
5. **缺测**：置 NaN，`valid=false`。**禁止插值填补**（填补放在 L2 中、且只在明确允许的场合使用）。

## 5. L2：处理

### 5.1 质量检查（`quality`）

| 检查 | 方法 | 输出 |
|---|---|---|
| 丢帧 | 帧 ID 不连续；`t_rel` 间隔偏离 1/帧率 | 丢帧列表、丢帧率 |
| 刚体缺测 | `valid` 统计 | 缺测率、最长缺测段 |
| 跳变 | 相邻帧位移超过 v_max / 帧率（v_max 可配，手持取 3 m/s），或姿态跳变超过阈值 | 跳变帧 |
| 机器人是否静止 | 躯干刚体全程的位置 / 姿态标准差 | 本层只报告不拦截（每帧各自变到 R 系，静止与否不影响正确性） |
| 刚体性 | 躯干刚体的 marker 在 R 系下的相互距离保持不变（用散点在 R 系聚类得到，不依赖资产点列） | 距离漂移；超过 0.5 mm 视为刚体松动或误识别 |

### 5.2 静止段切分（`static_seg`）

- **对象**：任一轨迹（球的 `p_W`、刚体位姿）。
- **判据**（v4 §7.7）：滑动窗口内位置标准差 < 2 mm，持续 ≥ 0.3 s；刚体另加姿态标准差阈值（例如 0.1°）。阈值全部可配。
- **段边界**：两端各收缩一个小余量（可配，例如 0.05 s），去掉起停时的过渡。
- **输出**：段列表，并标记“段内有缺测”“段内有跳变”。
- **注意**：只做切分，不做与相机段的配对（配对在下游）。但要输出段的起止时间与顺序号，供下游按顺序配对。

### 5.3 散点关联（`associate`）：不依赖 FZMotion 的 marker ID

FZMotion 的散点 ID 在遮挡后会改变，所以身份由几何决定：

| 场景 | 方法 |
|---|---|
| **R 系中静止的点**（躯干上的 marker、§1.5 特征点） | 把所有散点逐帧变到 R 系，再做空间聚类（半径 2–3 mm，带最小持续比例）。每个持久簇即一个物理 marker，簇 ID 跨 ID 变化保持稳定。簇中包括躯干刚体自己的 marker，这正好用于 5.1 的刚体性检查 |
| **W 系中运动的点**（标定球） | 先剔除落在 R 系静止簇附近的点（门限 10 mm），剩余点做逐帧最近邻链接，带速度门限；ID 变化不影响链接，只在门限外才断链；同一时刻有多个候选时报警，不自动选 |
| **打标签** | 配置中可给出 R 系下的种子坐标（例如“特征 3 约在 (x, y, z) 处”）；离种子最近的簇得到该标签。没有种子时只输出簇编号，由下游或人工指定 |

### 5.4 变到刚体系（`body_frame`）

- 逐帧计算 `p_R(t) = T_W_R(t)^{-1} · p_W(t)`。散点和刚体来自**同一动捕帧**，不需要插值。
- 只有跨源（例如 VRPN 刚体 + LuMoSDK 散点）时才插值：位置用线性或样条，姿态用 SLERP；插值点必须落在两侧有效帧之间，否则置 NaN。
- 可选：配置中给出带版本号的 `T_torso_R` 后，再输出 torso 系结果 `p_torso = T_torso_R · p_R`，并在元数据中记录所用版本。

### 5.5 段内聚合（`aggregate`）

- **先变换、后平均**：对段内每帧的 `p_R` 求均值，不用“平均 `p_W` 再乘平均 `T_W_R`”。
- 输出均值、协方差（3×3）、有效帧数、`p_W` 段内抖动标准差（衡量动捕自身噪声）、躯干在段内的运动量。
- 均值的标准误 = 协方差 / n。注意帧间相关会使它偏乐观，元数据中注明。

### 5.6 展布自检（`spread`）：采集现场的即时反馈

- 对 P2 的全部球心 `p_R,i` 去质心、求协方差后做 SVD，输出三个主方向的展布和**最小 / 最大奇异值比**。
- 刚体变换不改变奇异值，所以 R 系下的比值与 v4 §7.5 在相机系下的判据相同（< 1/20 即需补采）。在相机侧数据还没处理时，动捕侧就能先给出“还需往哪个方向补点”。
- 深度层覆盖要用相机系，本层不做。若配置中给了 URDF 名义的 `T_R_C`，可以给出粗略的深度直方图作为参考，并标注“名义值”。

## 6. 会话配置（YAML，概念字段）

| 分组 | 字段 |
|---|---|
| 输入 | CSV 路径列表；bag 路径与话题名；会话 ID |
| 源约定 | 轴约定（Y_Up / Z_Up）或显式 3×3 变换；长度单位覆盖；StartTime 时区；缺测表示 |
| 资产 | 躯干刚体名；物体刚体名列表；标定球的标签名 |

| 标签种子 | 特征点名 → R 系近似坐标 |

## 7. L3：数据产品契约

所有产品都是“一个目录”：表格用 Parquet（或 CSV，二选一后固定），另附 `meta.yaml`（Session 全部字段、配置哈希、代码版本、坐标约定声明、生成时间）。下游只依赖这里列出的字段。

| 产品 | 服务对象 | 坐标系 | 每行 | 主要字段 |
|---|---|---|---|---|
| **P1 `torso_features`** | §1.5 方法 A；刚体性检查 | R | 一个持久簇 | 簇 ID、标签（如有）、`p_R` 均值、协方差、帧数、持续比例；附表：躯干刚体全程的运动统计 |
| **P2 `ball_static_samples`** | MVP（v4 §4.3） | R（可选再给 torso 系） | 一个静止段 | 段序号、`t_start/t_end`（rel 与 abs，带时钟标签）、帧数、`p_R` 均值与协方差、`p_W` 抖动、躯干段内运动、质量标记；`meta` 中附展布自检结果 |
| **P3 `ball_trajectory`** | δt（v4 §6.3） | R | 一帧 | 时间（带时钟标签）、`p_R`、有效掩码、速度模长（中心差分，不平滑） |
| **P4 在线位姿** | 静态抓取 | torso | 话题消息 | 每个物体刚体的 `T_torso_obj = T_torso_R · (T_W_R)^{-1} · T_W_obj`；`frame_id = torso_link`；携带 `T_torso_R` 版本；任一输入过期（超过 N 帧没有更新）就停发，不发旧值 |
| **R0 `inspect` 报告** | 人工检查 | — | — | 资产清单、帧率、丢帧、缺测、跳变、刚体性、静止段时间线图、R 系点云三视图 |

**契约规则**：字段只增不改；改含义必须升主版本号；`meta.yaml` 中写 schema 版本。

## 8. 未知项与 M2 首次真机录制方案

这些未知项都已在代码中被隔离为配置或检查项，M2 用一次约 15 分钟的录制把它们全部定下来：

| # | 未知项 | 录制动作 | 判定 |
|---|---|---|---|
| 1 | 轴约定与手性 | 一个散点沿直尺依次 +X、+Y、+Z 移动 100 mm（以场地标记为准） | 规范化后各轴方向正确；x × y = z |
| 2 | 单位 | 同上，用直尺上的 100 mm | 读数为 0.100 m ± 1 mm |
| 3 | 四元数约定 | 一个测试刚体绕竖直轴转 90° 后静止 | 规范化后的四元数对应绕 +z 转 ±90°，符号与右手定则一致 |
| 4 | 资产点是实测还是模板 | 躯干刚体静止 30 s | 资产点相对刚体位姿的抖动为 0 → 模板；与散点抖动相当 → 实测 |
| 5 | 刚体默认原点与朝向 | 新建一个刚体后立即静止录制 | 刚体位置是否等于其 marker 散点均值；创建时刻的四元数是否为单位四元数 |
| 6 | VRPN 与 CSV 是否一致 | 同一会话同时录 VRPN bag 并导出 CSV | 轴、单位、数值一致（允许时间偏移） |
| 7 | 缺测表示 | 手遮住一个 marker 2 s | 观察 CSV 中缺测的写法 |
| 8 | 散点 ID 行为 | 遮挡后再露出，重复数次 | ID 是否改变；关联模块能否连上 |
| 9 | 丢帧与帧时间 | 整个会话 | 帧时间是否等于（帧号 − 1）/ 帧率 |
| 10 | 刚体 marker 是否也出现在散点列中 | 整个会话 | 决定 5.3 中剔除步骤的输入 |

M2 的结论写回 `FZMotion动捕系统要点_v4对接.md`（把“未确认”改为“实测确认”），默认配置也随之固定。

## 9. 测试与验收

### 9.1 合成数据（M0 必须先完成）

生成器 `sim` 输出**与 FZMotion 格式一致**的 CSV（标题行结构、mm、可选 Y_Up），注入：

- 已知的 `T_W_R(t)`（静止与微晃两种）；躯干 4–5 个 marker 及若干特征点；
- 一颗球在 W 中“移动 → 停稳 → 移动”，静止段的真值已知；
- 噪声（散点 0.2 mm）、缺测、丢帧、遮挡导致的 ID 变化、偶发跳变、一个干扰点。

### 9.2 验收标准（M1）

| 项 | 标准 |
|---|---|
| 解析 | 合成 CSV 往返无损；遇到欧拉角导出、左手系配置时正确报错 |
| 静止段 | 段数与真值一致；起止时间误差 ≤ 2 帧 |
| 关联 | ID 变化下球轨迹不断链；无静止簇误认为球 |
| P2 精度 | `p_R` 均值误差 ≤ 3σ/√n（σ 为注入噪声） |
| P1 | 簇数与注入 marker 数一致；刚体性检查能报出人为注入的 1 mm 松动 |
| 展布自检 | 对人为构造的近共面点集报警 |
| 可复现 | 同一输入 + 配置两次运行，产品逐位相同 |
