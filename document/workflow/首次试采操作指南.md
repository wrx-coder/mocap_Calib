# 动捕与 D435i：首次试采操作指南

**DDL 优先顺序**：先做 S1（真实 CSV）、S2（单位/轴）、S3（缺测）及共同靶球筛选，再做 C0/C1/C3（RGB-D与配对）。S0/S4/C2 在背景异常、姿态解释不清或互扰时追加，不要求每项独立审批。正式验收只保留软件合成闭环、少量真实试采、独立静态留出三项。

> 目的：弄清真实数据是什么、是否可信、两套设备能否同时看到部署球；**不是正式外参标定**。本文件只指导准备和试采，不表示已经实施或通过验收。
> 先由熟悉场地的管理员确认系统已标定、允许录制。不要自行移动动捕相机、改镜头、重设世界系或修改机器人正式刚体。

## 1. 先懂三个词

- **散点/Marker**：一颗反光标记在动捕世界中的三维位置；标定球要取这种实测点。
- **刚体/Rigid Body**：固定在同一物体上的一组 marker，其相互位置不变；软件由此给出物体的位置与朝向。球不必建成刚体。
- **检测管线**：机器人相机把图像变成球位置的一串处理步骤，不是动捕的 CSV 导出设置。厂家动捕手册不会告诉我们机器人相机代码走哪条路线。

相机三种输出路径：

| 路径 | 怎么得到三维点 | 主要待核查 |
|---|---|---|
| A：IR 亮斑 + 深度图 | 找到球的图像像素，再取该像素/邻域深度并反投影 | 深度可能是球前表面，不是球心；反光材料可能造成深度空洞；深度和 IR 需正确对应 |
| B：左右 IR 三角化 | 左右图都找到同一颗球，用视差与双目标定算三维位置 | 不依赖成品深度图，但依赖左右匹配、内外参；亮斑质心未必就是球心投影 |
| C：已有球心 xyz | 现成程序直接输出 x/y/z | 仍须追查底层是 A/B/球拟合哪一种、输出 frame/单位、是否已做半径或尺度补偿 |

不要求现在选算法。先保存能获取的原始观测和配置，再判断哪条路适合实际球。深度图是距离图，不等于已经完成球检测。

### 当前已找到的实际路径（优先于上述通用示例）

已有程序是**未标定外参的最小验证集，不是最终版**。设备为 D435i，内参已完成；保存真实 CameraInfo/标定文件即可，不另做内参标定。只沿用 RGB-D 观测，不把示例 TF/半径当实机真值。观测思路是：

```text
RGB 彩色图 → 分割目标 mask → mask 内提取对齐深度并筛除异常
→ mask 质心 + 深度反投影表面位置 → 沿视线补一次半径得到相机系球心
→ 现有 TF 换到 pelvis/local_world → 下游追踪
```

因此本轮**不把 IR 或双目作为必采主线**，优先采 RGB、aligned depth、CameraInfo 与检测 mask。相机系为实际配置的 color optical frame；已经补过半径的球心禁止再次加半径。示例配置不是当前运行配置，必须核实正在加载哪个 JSON、目标模型/类别与实际半径。

相机世界点已经用过未标定外参；标定须保留变换前的相机观测，不能只拿世界点来检验同一条外参链。当前示例录制列表未包含完整深度/mask，需要单独的标定录制清单，不直接照搬原 deploy recording。现有节点可能依赖 TF 才有有效 mask 输出，试采时须核验实际消息；必要时另案制作不依赖 world/pelvis 的离线观测适配，不能把伪造 TF 当数据条件已满足。

下述为独立编写的通用采集指导，不包含上游私有源码。

## 3. 进场准备与统一保存

### 物品

- 场地管理员协助；电脑/移动存储、拍设置截图的设备。
- 一颗标准反光 marker、一个哑光小刚性夹具及 4–5 颗固定 marker（非对称布置，避免共线；可有不同高度）；测试资产命名 `test_rigid`。
- 尺子/卷尺、稳定哑光支撑、可标记起点/终点的板；有条件用卡尺量球直径。
- 实际部署球；若暂未确定，记录测试球材质与直径，不称其为已确认部署球。
- 若机器人相机可用：可靠供电、可保存原始流的现有工具。此工作区尚无采集脚本，不能假装可直接运行标定命令。

### 多尺寸 marker 怎样分工：先过共同靶球闸门

用户确认目标是类似苹果大小的球体，现场有多种尺寸 marker。首次用尺/卡尺量实际直径，不能用“苹果大小”推断半径。不同物品分工：

- **胸部/测试刚体 marker**：组成位置与朝向可追踪的固定结构，不要求 RGB 模型识别这些小球。
- **torso 特征 marker**：对应 CAD 上已知特征，需补偿底座与球心高度。
- **共同靶球**：相机和动捕必须测同一球心；尺寸应接近实际工作目标，而且同时被 RGB 模型识别、具有有效深度、被动捕稳定测量。

**不能把贴在大球外壳上的小 marker 当大球球心。** 它的球心在表面外侧，偏差随大球朝向改变；随意减去一个半径也无法在未知朝向下消除。半球 marker、只贴一块反光胶带同样不能默认共心。

推荐先筛选现有整球反光 marker，选 2–3 个有代表性的尺寸，编号 `target_01/02/03`：

1. 拍全貌，测直径至少 3 个方向，记录完整球/半球、底座、表面和是否适合安全支撑。
2. 各自在工作近/中/远处稳定支撑 10 s，同时记录 RGB/mask、depth、动捕散点。优先接近目标尺寸；不以小球只在近处能识别作为全工作区合格。
3. 记录相机是否识别、有效深度数量/比例、是否碰边、动捕是否单点以及缺测。mask 和深度必须以消息内容确认，不仅看可视化。
4. 球心位置尽量固定，改变球表面方向/接缝朝向后重复；仅转表面时输出跳变说明外观/测量模型可能有偏置。若支撑使球心同时移动，不能把变化全部算传感器偏差，需如实记录。
5. 选择共同可见性可靠的候选，并说明动捕输出对应几何球心的依据；手册或稳定单点不能独立证明绝对球心正确，必要时请厂家确认大球算法/做进一步几何测试。

**通过条件**：工作区内 RGB 识别与数值深度可靠、动捕稳定且同物理球心有合理可核查依据；与现有感知不相容或共心未经确认时，不批准正式采几百点。若没有合适球，不随意把多个 marker 拼成“同球心”，而是单独规划已知几何的靶标，不在本主线新增自由偏移量。

### 所有片段的录制/导出做法

1. 拍摄软件版本、场地标定状态、世界系设置、相机型号/帧率/曝光/补光、自校准状态；先保存当前工程备份。请管理员确认自校准采集期间关闭，不清除已有标定结果。
2. Motar 录制区设置路径和下述片段名；按开始录制（应变为停止按钮），按片段步骤操作，再停止。每个实验单独录制，避免事后分不清。
3. 在工程管理找到该片段 → 右键“导出” → CSV；勾选**散点与刚体**。资产点仅在 S4 额外勾选作诊断，不能当测量真值。
4. 高级设置：打开表头，缩放 1，明确选择 mm，使用原录制帧率、全片段区间、绝对坐标与默认录制时码；记录坐标转换选项。不要默认“World”就是 Z-up。若选项不适用/不存在，拍照记录，不硬改。
5. 不做轨迹填充、平滑、一键优化、抽帧或用 Excel 另存修改 CSV；保留软件直接导出的文件、原录制、设置截图。四元数输出若不可选，先核对原始列是 X/Y/Z/W；不要套用 BVH 欧拉角选项。
6. 保存为 `data/raw/<session_id>/mocap/`、`camera/`、`notes/`；日志写明片段名、操作顺序、实测距离、质量颜色与异常。原始数据目录默认不入 Git，公开仓库不要上传个人信息或完整现场画面。

## 4. 动捕侧必做片段

### S0：环境与空场，10–20 s

**采什么**：设备配置、无测试球时的背景散点与当前系统状态。

**怎么采**：保留固定资产，不移动正式设备；移走试验球与手上反光物，录 `S0_background`。截一张 3D 场景、一张代表性 2D 相机图。

**为什么**：识别背景假点；后续区分球和已有 marker；保存当时系统状态。

**产物/检查**：原录制、CSV、配置截图、相机型号与帧率。若背景散点很多先请管理员排查；不自行大面积蒙版遮工作区。

### S1：静止测试刚体 + 一个独立散点，30 s

**采什么**：同帧刚体位姿和不属于该刚体的散点，及其静态抖动。

**怎么采**：仅用测试夹具 marker 建 `test_rigid`，拍照标注 marker；另一标准 marker 放在独立稳定支撑上，**不要加入刚体**。确认质量颜色良好后录 `S1_static`，全程不碰支撑。停止并按统一设置导出。

**为什么**：获得真实 CSV 黄金样例，确认 Marker/刚体类型、表头与位置/姿态字段；估计动捕静态噪声。

**产物/检查**：两个物体布局照片、完整 CSV 与片段。确认有刚体位置及四元数、独立散点三维列、持续帧时间；没有散点列时回查勾选项而不是用资产点顶替。抖动超过 2 mm 时作为问题记录，不能立即认定设备坏或强行调低数据。

### S2：已知方向与长度平移，约 1–2 min

**采什么**：三个独立方向的点位移，核对单位/坐标方向/手性。

**怎么采**：由管理员在场地指出软件世界轴的实际方向，截图标记；沿每一方向用尺子布置起点 A、终点 B，球心基准保持一致。优先 200 mm，空间允许可 500 mm；每轴依次 A 停 5 s → 移到 B 停 5 s → 回 A 停 5 s，记录 `S2_axis_x/y/z`。垂直方向用稳定支撑，避免手抖；不要凭屏幕观看方向代替物理轴。

**为什么**：防止 mm/m、导出缩放、轴交换/反向等“代码能跑但结果错误”的问题。

**产物/检查**：各轴实测位移、起终点照片和 CSV。位移向量应与记录方向相符、长度与尺测误差相容；尺测不是精密标定真值，不用它宣称亚毫米精度。无法确定原世界轴时记录实际物理位移对应的数据向量，交给解析/几何工具核验，不猜轴。

### S3：遮挡与恢复，约 45–60 s

**采什么**：散点缺测、ID 恢复及刚体丢失时的数据行为。

**怎么采**：独立 marker 保持位置不动，先可见 5 s → 用哑光遮挡物遮所有可见方向约 2 s → 移开停 5 s，重复 3 次，录 `S3_marker_occlusion`。另录 `S3_rigid_occlusion`，在不碰 marker 的条件下遮挡测试刚体足够多的点使其短暂丢失，再恢复。不要遮场地正式资产。

**为什么**：确认空值/0/NaN/旧值保持、是否掉列、散点 ID 是否改变，避免误用被补出的“点”。

**产物/检查**：标注每次遮挡区间的日志/视频与原 CSV。若遮挡期间仍输出恒定旧值，记录并确认状态字段/软件是否预测，不将其当新实测点；若未真正丢失，记录失败原因再试一次，不伪造缺测样例。

### S4：刚体朝向与资产点语义，约 1–2 min

**采什么**：刚体姿态、可对应的 marker 与资产点坐标。

**怎么采**：先用测试刚体静止 10 s，拍照并标出不对称 marker；绕已知竖直方向转约 +90° 停 10 s，再回起姿停 10 s，录 `S4_rigid_rotation`。保存散点、刚体以及额外资产点。可再将测试刚体平移一段停稳，记录方向与距离。正式刚体不参与。

**为什么**：结合相对姿态变化检查四元数方向；验证刚体逆变换后固定 marker 的局部坐标是否稳定，并调查资产点是否可能是模板/预测值。

**产物/检查**：旋转方向照片、原 CSV、测试工程与资产（可保存时）。仅“世界系资产点不抖”不足以证明是模板；要与对应散点一起转换到刚体系，分析点间距、局部坐标、遮挡状态。若仍无法区分，标为未知，主线继续只用实测 Marker。

### S5：实际球能否作为单散点，约 2–4 min

**采什么**：部署尺寸球在近/中/远及边缘的识别情况。

**怎么采**：用稳定哑光支撑；记录球直径/表面材质和照相。先近处停 10 s，中距停 10 s，远处停 10 s，每处缓慢转球改变表面方向再停；在左右/高低边界再各停 5–10 s。距离以实际工作区安全有效范围为准，非强制 1–4 m。观察是否单个散点、掉点或多个假点；保存代表性 2D 图。需要调圆度/面积/阈值时由管理员逐个改参数，保存改前/后截图，不同时改很多项。

**为什么**：标准小 marker 可测并不保证大反光球也被稳定检测；胶带接缝、饱和与部分可见会造成位置偏差。

**产物/检查**：位置编号、粗测距离、球方向、设置、CSV 和截图。稳定成一个散点是第一步，不证明测到精确球心；球转动引起位置系统变化须回查材料/球心模型，不能交给外参随意吸收。

## 5. 相机可用时追加片段（否则明确留作阻塞项）

### C0：型号、流与现有代码盘点

**采什么**：机器人相机型号/序列号、RGB/原始深度/对齐深度流、内参/畸变/相机内部外参、实际启动配置和一条输出。左右 IR 本轮非必需；仅在 RGB-D 路径失败且决定评估替代路线时追加。

**怎么采**：用现有驱动/查看工具列出启用流；保存实际加载的感知节点 JSON、其引用的算法 JSON、相机 JSON 和 TF 配置/URDF，记录分支提交、分辨率、曝光、发射器、对齐/滤波与 depth units。记录 `target_radius` 的实际上下限及物理球直径；与程序已补偿球心的状态一起保存。不得用示例配置替代实际启动文件。

在已启动且不接入执行器的感知环境，可先用只读查询：

```bash
ros2 node list
ros2 topic list -t
# 若实际节点名不同，使用上一条输出中的真实名称：
ros2 param get /target_perception_node config_path
```

若是 native 部署而非该 ROS 节点，保存其实际启动命令与配置，待检查对应执行路径；本轮不启动机器人控制程序。

**为什么**：分清 A/B/C，确定标定参数与 residual；无需现在手写算法。具体采集命令等硬件/驱动确认后给，不编造通用 ROS 话题。

### C1：深度与双目可用性小样本，约 1–3 min

**采什么**：球在同一静态位置的 RGB、对齐到 RGB 的深度、CameraInfo、mask 及检测输出；尽量同时保存原始深度和相机内部外参，便于检查 depth-to-color 几何。

**怎么采**：按 S5 中至少近/中/远三个位置，各停 10 s；各位置保留原始流与同时的动捕散点，并编号。检查 RGB 分割是否覆盖真实球、mask 是否碰图像边界、深度是否空洞/背景穿透、输出是否掉帧。给球贴/包反光材料后必须再检验 RGB 模型仍能识别，不能默认外观改变不影响识别。用哑光参考物在相近位置额外录一段作为深度可用性对照，不替代球的最终观测。

**为什么**：当前 RGB-D 路径同时依赖分割和有效深度，任一失败都不能靠最后世界点“看起来合理”通过。先验证部署球/动捕用球是不是同一颗、外观是否兼容，再做正式采样；只有当前路线实测失败才单独评估 IR/双目，不预先扩散工作范围。

**产物/检查**：原始流、配置/内参、编号、mask、空洞/饱和截图、已有输出。截图不能代替数值深度或带元数据的记录。根据该分支示例，核查现场真实话题（命名空间可能不同）：

- `/camera/color/image_raw`
- `/camera/aligned_depth_to_color/image_raw`
- `/camera/color/camera_info`
- `/camera/depth/image_rect_raw`（支持时保存）
- `/perception/target_mask` 与 `/perception/target_overlay_source`（保留 mask 对应图像/时间）
- `/perception/target_point_world`（仅诊断，不能作为独立相机观测）
- `/tf`、`/tf_static`（保存现有转换来源，不当外参真值）

相机系球心、表面深度与有效深度样本数在代码内部可用，但目前未确认独立发布接口；先完整记录输入，后续在本工作区重建外参前的观测。深度/mask 的录制须核验 QoS 和实际消息数量，只有话题名称不等于录到了数据。

### C2：双向 IR 互扰，四种状态各 10–20 s

**采什么**：机器人深度相机发射器与动捕补光开关组合下，RGB 分割/深度有效性与动捕散点的假点、缺测、饱和。仅当确有 D435 系列设备和允许切换时执行对应开关；不要求 IR 图成为主线观测。

**怎么采**：由管理员确认允许临时切换测试设置；测试球和两套相机不动，记录“动捕补光开/关 × 机器人相机发射器开/关”四段并保存设置。动捕补光关时可能不再跟踪，这是正常对照，不要求输出真值；每段恢复后确认设置。若系统不允许独立切换某项，跳过并记录，不停止整个场地服务。

**为什么**：分清假斑点源与互扰；不能把关闭部署必需补光的状态当作最终通过状态。

**产物/检查**：两侧记录、设置、异常日志；最终必须在计划部署的开关状态下共同观测有效。未找到可靠状态时暂停正式单球采样。

### C3：小批静态点配对预演，12–20 个位置

**采什么**：每个独立位置的双侧有效静态段和显式编号。

**怎么采**：覆盖至少 3 个距离与几个视场方向，每位置停 3–5 s（首次试采故意多留余量）；日志记录 `sample_id`、两侧片段/段编号、粗略起止时间。各自录制前后增加一个较长静止位置作顺序核验。只静态平均，不追求逐帧精确同步。

**为什么**：提前发现漏段、编号歧义、共同视场不足和相机侧静态阈值问题，避免正式 200–400 点全批作废。

**产物/检查**：一对一配对表、原始记录；不为凑数强行对齐漏段。此小批只作数据链路预演，不以它宣称达到最终外参精度。
